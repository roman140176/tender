# EIS spike — доказать, что живой запрос к ЕИС возвращает данные

**Назначение.** До любых вложений в прод-инфру, AI-слой и монетизацию — проверить
самое рискованное допущение всего проекта: что реальный запрос к ЕИС с нашим
токеном **возвращает данные, а не «гасится»**. Мы ни одного живого запроса ещё
не делали, поэтому неизвестно, работает ли ГОСТ-handshake, принимается ли токен и
совпадает ли форма SOAP-конверта с боевой WSDL.

Это спайк — **не прод**. Сценарий: поднял дешёвый временный RU-VPS → прогнал →
получил диагноз → выкинул VPS.

## Почему именно так

- **RU-IP** — ЕИС-интеграция доступна только с российских адресов.
- **ГОСТ-TLS** — `int44.zakupki.gov.ru` говорит по ГОСТ-шифрам. Берём `gost-engine`
  (бесплатный движок OpenSSL), **КриптоПро не нужен** — истёкший триал не блокер.
  > ⚠️ **КРИТИЧНО (проверено 2026-06-20):** ГОСТ-TLS-шифронаборы через `gost-engine`
  > на **OpenSSL 3.x — ТУПИК** (ENGINE-API в 3.0 устарел, TLS-handshake с ГОСТ не
  > поднимается; крипто-примитивы грузятся, но cipher не негоциируется). **Бери VPS на
  > OpenSSL 1.1.1 — Debian 11 (bullseye) или Ubuntu 20.04** — там `gost-engine` ГОСТ-TLS
  > работает полностью, и это ровно тот бесплатный путь, который ещё НЕ проверяли (ради
  > него спайк и затеян). Альтернатива — `stunnel` + КриптоПро CSP, но это платная
  > лицензия (триал истёк). См. [[eis-live-access-requirements]] в памяти.
- **Токен, не КЭП-на-запрос** — в коде авторизация заголовком
  `individualPerson_token` (см. `app/Adapters/Eis/SoapEisGateway.php`). КЭП нужна
  была один раз для выпуска токена; токен годен до декабря 2026. Значит спайк
  самодостаточен — Mac/КЭП не требуются.

## Запуск

На временном RU-VPS (Debian/Ubuntu), от root:

```bash
# 1. Поставить ГОСТ-движок и сгенерировать openssl-конфиг
sudo bash scripts/eis-spike/setup-gost.sh

# 2. Сырой staged-probe (openssl + curl) — НЕ зависит от PHP/Laravel
export OPENSSL_CONF=/etc/ssl/gost.cnf
bash scripts/eis-spike/probe.sh
#   варианты:
#   REESTR=0173200001425000123 bash scripts/eis-spike/probe.sh   # лёгкий одиночный вызов
#   REGION=78 SUBSYSTEM=RI223 DATE=2026-06-19 bash scripts/eis-spike/probe.sh

# 3. (опц.) Прогнать через РЕАЛЬНЫЙ прод-код SoapEisGateway.
#    Требует, чтобы PHP-curl тоже умел ГОСТ (системный openssl с движком).
php artisan eis:probe --region=77 --subsystem=PRIZ
php artisan eis:probe --reestr=0173200001425000123
```

`probe.sh` доказывает транспорт сырым curl; `eis:probe` — что данные доходят до
прод-кода (парсинг `archiveUrl`/`noticeXml`). Сначала probe.sh, потом артизан.

## Дерево диагнозов

`probe.sh` идёт тремя стадиями. Смотри, на какой ломается:

| Симптом | Стадия | Диагноз | Что делать |
|---|---|---|---|
| `s_client` не CONNECTED | 0 | Нет RU-IP / DNS / firewall | Проверить, что VPS реально в РФ; `ping`/`nc int44.zakupki.gov.ru 443` |
| CONNECTED, но шифр не ГОСТ и curl `000` | 0–1 | ГОСТ-движок не активен ИЛИ **OpenSSL 3.x** (известный тупик) | Проверить `OPENSSL_CONF`/`openssl engine gost -t`/`dynamic_path`. Если OpenSSL 3.x — пересоздать VPS на 1.1.1 (Debian 11 / Ubuntu 20.04) |
| curl `000`, ошибка про SSL/handshake | 1 | ГОСТ-handshake падает | Версия движка/шифров; попробовать `-tls1_2`, проверить `gost-engine` |
| HTTP **401/403** | 1 | **Токен отклонён / нет прав на метод** | Токен протух/не активирован под метод; проверить регистрацию интеграции в ЛК ЕИС |
| HTTP **200** + `archiveUrl`/`noticeXml` | 1 | ✅ **ПАЙП РАБОТАЕТ** | Двигаемся к продакшн-VPS |
| HTTP **200** + `<Fault>` | 1 | **Форма конверта vs WSDL** | Сверить имена элементов с актуальной WSDL/Альбомом ТФФ (NOTE в SoapEisGateway) |
| HTTP **200**, пусто (ни данных, ни Fault) | 1 | Пустой период ИЛИ иная структура ответа | Сменить дату/регион; снять реальный ответ и сверить теги |
| Stage 1 ок (`-k`), Stage 2 `000` про cert | 2 | **Нет корневого CA Минцифры** | Транспорт работает; для прода поставить «Корневой сертификат Минцифры (ГОСТ)» в trust store |

**Ключевое разделение:** `000`/handshake-фейл = *транспорт* (наша инфра, чиним
VPS/движок). HTTP-ответ с любым кодом = *транспорт прошёл*, дальше вопрос токена
или формы конверта (чиним код/доступ). Это две принципиально разные цены лечения.

## Что дальше — по результату

- **✅ 200 + данные** → допущение подтверждено. Поднимаем постоянный RU-VPS как
  ГОСТ-прокси (он же даёт RU-IP), прод-сервер остаётся чистым. Вешаем guard на
  протухание токена (декабрь 2026) через существующий канал уведомлений.
- **🔁 200 + Fault** → транспорт есть, чиним SOAP-конверт по живой WSDL — это
  дёшево, проект жив.
- **🔒 401/403** → разбираемся с регистрацией интеграции/токена в ЛК ЕИС.
- **⛔ транспорт не поднимается даже с RU-IP** → самый дорогой диагноз; вот тут
  имеет смысл честно переоценить, стоит ли городить ГОСТ-инфру, или брать данные
  у агрегатора, который уже решил крипту.

## Файлы

- `setup-gost.sh` — ставит `gost-engine`, генерирует `/etc/ssl/gost.cnf`, проверяет загрузку движка.
- `probe.sh` — staged-probe (openssl s_client → curl -k → curl с CA), печатает диагноз.
- `app/Console/Commands/EisProbeCommand.php` — `php artisan eis:probe`, тот же запрос через прод-код.
