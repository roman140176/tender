# Этап A «Тендерный радар» — роадмап планов реализации

Спека: `docs/superpowers/specs/2026-06-05-tender-radar-design.md`. Каждый план — отдельный документ в этой папке, производит работающее, протестированное ПО. Планы пишутся последовательно, по мере выполнения предыдущих (поздние планы опираются на фактический код).

| План | Содержание | Результат («работает …») | Статус |
|------|-----------|--------------------------|--------|
| **A1** | Каркас Laravel 12 + Inertia/Vue, docker-compose dev, CI, полная схема БД (миграции/модели/enums/factories), tenant-изоляция, auth login-only, сидеры | приложение поднимается, логин работает, схема накатана, тесты моделей и изоляции зелёные | план готов |
| **A2** | CRUD направлений (search_profiles) и ключей 6 типов, валидация активации, настройки компании, вкл/выкл источников | через UI можно завести направление с ключами | — |
| **A3** | Normalizer, Deduplicator (каскад + content_hash), ручной импорт CSV/XLSX/JSON/URL (chunk), source_collect_runs | загруженный файл превращается в записи `tenders` без дублей | — |
| **A4** | Scorer (все правила §7 спеки), кандидатный запрос (FTS + trigram), MatchProfileJob, company_tenders/tender_matches, risk_flags/recommendation, автоматчинг после импорта, golden-набор | импортированные закупки матчатся и скорятся, балл объясним | — |
| **A5** | UI закупок: список с фильтрами (13.2), карточка (13.3), статусы (13.4), комментарии, история; просмотр логов запусков | менеджер работает с закупками в кабинете | — |
| **A6** | Адаптер ЕИС: скачивание архивов выгрузок, потоковый ZIP→XML, маппинг извещений 44/223-ФЗ, оркестратор → чанк-джобы, Horizon | живые закупки ЕИС приходят в систему по кнопке | — |
| **A7** | Telegram-уведомления (полный формат 14.1), антидубль, ручной запуск радара из UI, дашборд-минимум | релевантная закупка прилетает в Telegram | — |

Предусловия A1: на хосте PHP ≥ 8.3, Composer 2, Node 20+, Docker; доступ к Госуслугам для регистрации в ЕИС оформляется параллельно (нужен к A6).
